## US-055: Fix Footer Position When Few Goals
**Date**: 2026-01-22
**Status**: Completed

### What was done:
Fixed the footer positioning issue in the Daily Goals screen where the navigation buttons (Manage Goals, Reports) would float up when there were few or no goals.

### Implementation details:
1. Added explicit `height: 500px` to `html, body` (in addition to existing min/max-height) to ensure the height chain works properly with percentage-based heights.

2. Added `min-height: 100%` to screen container classes (`.view-goals-screen`, etc.) to ensure they fill the available space.

3. Added `margin-top: auto` to `.screen-footer` - this CSS trick pushes the footer to the bottom of the flex container when there's extra space.

4. Changed `.goals-list-container` from `flex: 1` to `flex: 1 1 auto` for more explicit flex behavior.

### Files modified:
- `src/popup/popup.css` (lines 188-195, 359-369, 403-414, 488-502)

### Key learnings:
- In flexbox layouts, `height: 100%` only works when the parent has an explicit height (not just min/max-height)
- `margin-top: auto` on the last flex item pushes it to the bottom of the container
- `flex: 1 1 auto` is more explicit than `flex: 1` (shorthand for `flex: 1 1 0`)
- The Chrome extension popup has fixed dimensions (380px width, 500-600px height)

### Acceptance criteria met:
- Footer buttons stay at bottom regardless of goal count
- Works with 0 goals (empty state)
- Works with 1-2 goals
- Content area scrolls when many goals
- Layout remains consistent across all scenarios

## US-057: Dynamic Goal Form Fields Based on Type
**Date**: 2026-01-22
**Status**: Completed (Already Implemented)

### What was done:
Verified that the dynamic goal form fields feature was already implemented in the codebase. The Add/Edit goal form shows only relevant fields based on the selected goal type.

### Implementation details (pre-existing):

1. **HTML Structure** (`src/popup/popup.html`):
   - `#timer-target-group` (lines 118-153): Contains hours/minutes inputs for timer goals
   - `#counter-target-group` (lines 156-170): Contains target count input for counter goals
   - Both groups have the `target-input-group` class for shared styling
   - Counter group starts with `hidden` class (timer is default type)

2. **JavaScript Logic** (`src/popup/popup.js`):
   - `updateTargetInputVisibility(type)` (lines 1914-1937): Toggles visibility based on type
   - `setFormType(type)` (lines 1871-1897): Sets form type and calls updateTargetInputVisibility
   - `handleTypeSelection(type)` (lines 1903-1906): Handles type button clicks
   - `handleGoalFormSubmit()` (lines 1605-1724): Validates only relevant fields based on type
   - `openGoalModal('edit', goal)` (lines 1458-1521): Pre-fills form and shows correct fields in edit mode

3. **CSS Styles** (`src/popup/popup.css`):
   - `.target-input-group` (lines 3108-3111): Base styles with smooth transitions
   - `.target-input-group.hidden` (lines 3114-3119): Hidden state with opacity: 0, max-height: 0
   - Transition: `opacity 200ms ease, max-height 200ms ease, margin 200ms ease`

### How it works:
- **Timer type**: Shows `#timer-target-group` (hours/minutes inputs), hides `#counter-target-group`
- **Counter type**: Shows `#counter-target-group` (target count input), hides `#timer-target-group`
- **Checkbox type**: Hides both target groups (target is always 1)

### Files involved:
- `src/popup/popup.html` (lines 118-170)
- `src/popup/popup.js` (lines 1605-1937)
- `src/popup/popup.css` (lines 3108-3119)

### Key learnings:
- The feature was implemented as part of earlier user stories (US-025, US-026)
- Good practice to check if functionality already exists before implementing
- The hidden class approach with CSS transitions provides smooth animations

### Acceptance criteria met:
- Timer selected: show hours/minutes inputs only
- Counter selected: show target count input only
- Checkbox selected: hide all target inputs
- Fields animate in/out smoothly (200ms CSS transitions)
- Form validates only visible fields (conditional validation in handleGoalFormSubmit)
- Edit mode pre-selects type and shows correct fields (setFormType called in openGoalModal)

## US-058: Full-Page Add/Edit Goal Screen
**Date**: 2026-01-22
**Status**: Completed

### What was done:
Replaced the modal/popup for Add/Edit goal with a dedicated full-page screen. This provides better UX with more space for form fields and maintains consistency with the app's navigation pattern.

### Implementation details:

1. **Screen Registration** (`src/popup/popup.js`):
   - Added `GOAL_FORM: 'goalForm'` to SCREENS enum
   - Added `[SCREENS.GOAL_FORM]: 'screen-goal-form'` to SCREEN_IDS mapping
   - Added case in `renderCurrentScreen()` switch to call `renderGoalFormScreen()`

2. **HTML Structure** (`src/popup/popup.html`):
   - Added new screen container: `<div id="screen-goal-form" class="screen">`
   - Removed the old goal form modal HTML (US-022 modal code)

3. **New Screen Rendering** (`src/popup/popup.js` - ~600 lines added):
   - `goalFormState` object to track mode ('add'/'edit') and editingGoalId
   - `openGoalFormScreen(mode, goal)` - Sets state and navigates to form screen
   - `renderGoalFormScreen()` - Renders full-page form with:
     - Header with back button and dynamic title ("Add New Goal" / "Edit Goal")
     - Main content area with all form fields (title, type selector, targets, timeframe)
     - Footer with Cancel and Save buttons
   - `attachGoalFormScreenListeners()` - Event listeners for all form interactions
   - `setGoalFormScreenType()` - Updates type selection and shows/hides target inputs
   - `setGoalFormScreenTimeframe()` - Updates timeframe selection and hint text
   - `prefillGoalFormScreen()` - Pre-fills form data for edit mode
   - `handleGoalFormScreenSubmit()` - Validates and saves goal (add or edit)

4. **Navigation Updates** (`src/popup/popup.js`):
   - Add Goal button now calls `openGoalFormScreen('add')` instead of `openGoalModal('add')`
   - Edit button (handleEditGoal) now calls `openGoalFormScreen('edit', goal)` instead of `openGoalModal('edit', goal)`
   - Back and Cancel buttons navigate to SCREENS.MANAGE_GOALS

5. **CSS Styles** (`src/popup/popup.css` - ~80 lines added):
   - `.goal-form-screen` - Full-height flex container
   - `.goal-form-header` - Consistent header with back button, title, spacer
   - `.goal-form-content` - Scrollable content area
   - `.goal-form-footer` - Fixed footer with action buttons

### Files modified:
- `src/popup/popup.html` (removed modal, added screen placeholder)
- `src/popup/popup.js` (lines 78-95, 143-162, 1133-1140, 1180-1765, 1821-1824, 4474-4484)
- `src/popup/popup.css` (lines 1309-1388)

### Key design decisions:
- Form fields are dynamically rendered in JavaScript (not static HTML) for consistency
- Reused existing validation helpers (showInputError, clearInputError)
- Form state is managed via dedicated `goalFormState` object, not DOM attributes
- Old modal functions retained (but unused) for backward compatibility with tests

### Architecture notes:
- Full-page screens follow consistent pattern: header (back, title, spacer) + main + footer
- Navigation is unidirectional: Manage Goals → Goal Form → Manage Goals
- Form submission navigates back automatically on success
- Error handling shows inline errors without blocking navigation

### Acceptance criteria met:
- New SCREENS.GOAL_FORM screen added
- Full-page layout with header (back button, title)
- All form fields from current modal (title, type, targets, timeframe)
- Save/Cancel buttons at bottom
- Back navigation returns to Manage Goals
- Old modal code removed from HTML
